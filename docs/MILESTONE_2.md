# Milestone 2 — The First Connection

> 目标不是增加功能，而是回答一个问题：
>
> **玩家在第一次打开项目后的 30 秒内，会不会觉得这不是一堆代码，
> 而是一只愿意回应自己的狗？**

---

## 这一阶段做了什么

一个房间。一只狗。**没有 UI、没有菜单、没有按钮。**

玩家唯一能做的事是「摸它」。

然后：

```
第一次摸   →  它看向你
继续摸     →  它慢慢走过来
            →  坐到你旁边
            →  摇尾巴
            →  闭眼享受
快速连点   →  它觉得烦，走开
安静等一会 →  它消气了
冷落很久   →  它慢慢忘了你
```

玩家什么按钮都没点，只是摸。但会觉得「它认识我了」。

```powershell
npm run dev          # → http://localhost:5173
```

打开后整个屏幕就是那个房间。用鼠标（或手指）按住狗。

默认体验刻意保持纯净 —— 否则第一眼看到的是"一个工具"而不是"一只狗"。

## 核心机制

### 1. 羁绊（Bond）—— 「它认识我吗」

不是"点五次解锁五个动作"的计数器，而是一个 **连续衰减的量** `bond ∈ [0,1]`。

```
bond 落在这张阶梯的哪一级  →  它现在的亲近程度
  0.00  LookAt      看向你
  0.32  Approach    靠近
  0.55  Sit         坐到旁边
  0.76  WagTail     摇尾巴
  0.93  PetEnjoy    闭眼享受
```

**三条规则合起来才是"生命感"：**

| 行为 | 结果 | 玩家感受 |
|---|---|---|
| 温柔抚摸 | bond 上升 | 它越来越亲近 → 「它记得我」 |
| 冷落一会儿 | bond 缓慢衰减 | 它没那么热情了 → 「它有自己状态」 |
| 快速连点 | bond 下降 | 它生气了 → 「它有自己的意愿」 |

**缺了衰减，它就只是进度条。**

#### 边际递减

```
gain = gainPerPet × (1 - bond) ^ 0.6
```

羁绊越低涨得越快（陌生狗容易建立初步信任），越高越难再进一步
（真正的亲密需要长期陪伴）。没有这一条，5 次点击就"通关"了 —— 那不像生命，像任务。

### 2. 情绪（Mood）—— 当下这一刻的感觉

四个量，刻意保持最小：

| 量 | 范围 | 作用 |
|---|---|---|
| `valence` 愉悦 | -1..1 | 被摸舒服 → 上升；被烦 → 下降 |
| `arousal` 兴奋 | 0..1 | 驱动尾巴摆幅与呼吸频率 |
| `annoyance` 烦躁 | 0..1 | 超阈值 → 走开 |
| `comfort` 安心 | 0..1 | 持续上升 → 闭眼享受 |

**情绪不直接控制行为，而是输出一张「修饰表」。**
状态机、动画层、过程动画层都从这张表读取 ——
所以"被摸时尾巴摆得更欢"不需要为每个状态写动画，它自动成立。

所有情绪都会**自愈**回中性。没有自愈，狗会"越摸越疯"或"永远生气"。

### 3. 骚扰判定 —— 「连续点」的边界

判定单位是 **抚摸会话**，不是结算次数。

- 一次 420ms 的温柔按住会结算约 4 次有效抚摸
- 若按结算次数计入窗口，正常地"摸一会儿"就会被判成骚扰

因此只统计"新一次抚摸会话的开始"。

阈值用 `npm run calibrate` 标定，而不是靠手感：

```
节奏              结果         判定
A 缓慢深情 900/2200  始终未走开    ✓ 不应生气
B 正常抚摸 700/1400  始终未走开    ✓ 不应生气
C 轻快抚摸 400/900   始终未走开    ✓ 不应生气
D 稍显急促 300/500   始终未走开    ✓ 不应生气
E 快速连点 150/250   第6次走开     ✓ 应生气（2.5 次/秒，已是"戳"）
F 连点骚扰  80/70    第7次走开     ✓ 应生气
G 疯狂连点  50/40    第8次走开     ✓ 应生气
```

**E 是「抚摸」与「戳」的分界线。** 人手自然抚摸的最低节奏约 2 次/秒，
E 达到 2.5 次/秒 —— 生理上已经不是抚摸。这个边界必须清楚，
否则"连点 → 走开"这条核心体验就没有可触发的区间。

### 4. 原谅 —— 会生气，但不会记仇

闹别扭结束时**强制平复情绪**。

若只靠自然衰减（约 0.3/s），会出现"闹别扭结束了但烦躁仍高于阈值"，
狗会立刻再次走开，形成无限循环 —— 玩家看到的是"它一直在生气，怎么哄都没用"。

Milestone 2 要传达的是「它有情绪，但会消气」，不是惩罚玩家。

## 数据驱动：换 JSON 就是另一只狗

三个灰盒犬种构成对照实验。**`src/core/` 零改动。**

| | graybox | graybox-shy | graybox-swift |
|---|---|---|---|
| 定位 | 中性基准 | 慢热害羞 | 敏捷亢奋 |
| `energy` | 0.5 | 0.35 | 0.95 |
| `shyness` | 0.5 | **0.88** | 0.10 |
| `gainPerPet` | 0.22 | **0.11** | 0.22 |
| 摸 5 次后羁绊 | 0.99（闭眼） | **0.33（仍在观望）** | — |
| 连点到走开 | 第 10 次 | **第 9 次** | **第 7 次** |

玩家会立刻发现：「换狗以后真的不一样。」

## 架构

### 分层

```
PointerAdapter      鼠标/触摸归一化
      ↓
GestureRecognizer   点击 / 长按 / 连点识别
      ↓
InteractionSystem   命中检测 + 按住时长累计
      ↓
World               编排：羁绊 → 情绪 → 状态机 → 动画
      ↓
StateMachine        数据驱动的效用裁决
      ↓
RenderState         不可变快照
      ↓
GrayboxRenderer     Pixi 分层精灵
```

### 新增的 core 模块

```
core/affection/
  BondSystem.ts      羁绊阶梯（Milestone 2 的核心）
  MoodSystem.ts      情绪四量 + 骚扰时间窗口

core/interaction/
  PointerAdapter.ts     鼠标/触摸/笔 归一化
  GestureRecognizer.ts  点击/长按/连点识别
  InteractionSystem.ts  命中检测 + 抚摸会话

core/fsm/
  interactionStates.ts       六个互动姿态
  interactionTransitions.ts  羁绊阶梯的裁决规则
```

### 互动状态

```
LookAt     看向玩家     最低成本、最先出现的回应
Approach   靠近玩家     速度用 walkSpeed 的 0.7 倍 —— "慢慢"是重点
WagTail    摇尾巴       只需拉高兴奋度，尾巴自动摆得欢
PetEnjoy   闭眼享受     松手立刻退出（闭眼是回应，不是循环动画）
Annoyed    烦躁         转头避开玩家
Retreat    走开         走向远处 + 生闷气冷却
```

这些是**通用互动姿态**，不是犬种专属。
差异全部来自 `affection.bonding.ladder` 与 `affection.annoyance.*`。

## 开发中修掉的真实缺陷

记录在此，避免后人重复踩坑。

### 1. `Walk → Idle` 守卫形同虚设

给迁移加了 `guard` 后，狗仍走了 0.5 秒就被拉回 ——
因为状态基础偏好（`stateWeights`）会让状态**绕过所有迁移守卫**成为候选。

修复：引入**准入守卫**，只有通过准入的状态才能作为切换目标。

### 2. 效用门槛在份额尺度上无解

`stateWeights` 是"份额"（总和为 1），而迁移效用是绝对值。
只要门槛与份额同尺度，高偏好状态就会在两个极端之间摆动 —— 试了四版都不对。

修复：门槛只比较**效用**，份额只负责"选谁"。

### 3. 温柔地摸被判成骚扰

一次 420ms 的按住会结算 4 次有效抚摸，瞬间超过阈值 4。
表现为"羁绊刚涨到 0.49 就崩回 0"。

修复：骚扰判定只统计**抚摸会话**，不统计结算次数。
并新增 `npm run calibrate` 用扫描标定阈值。

### 4. `leaveAt: 1.0` 导致狗永远不走开

`annoyance` 经 `clamp01` 上限为 1，永远达不到 1.0。
这个 bug 在两种犬种上各出现一次，画面上完全看不出是配置错误。

修复：配置改为可达值，并在校验器中**强制要求 `leaveAt ≤ 0.85`**
（为性格修正的乘子留余量）。

### 5. `PetEnjoy` 松手后仍闭眼

`onUpdate` 只设了 `enjoying = false`，却 `return null` ——
状态的退出必须**返回目标状态**才能真正迁移。
表现是"松手后它一直闭眼"，看起来像卡死。

### 6. 房间地板渲染成品红

把 `0x1e1e26` 手算成 `2031654`（实际应为 `1973798`），
JSON 完全合法、校验通过，但地板刺眼。

修复：校验器新增**饱和度检查**（RGB 通道差 > 48 报错）。

### 7. 浏览器实测"狗反应很慢"

实测发现 rAF 只以 **8.2% 速度**运行（5 tick/s 而非 60）。
一度以为是产品 bug，实为无头浏览器未合成页面导致 rAF 被节流。

**教训**：用无头浏览器测时序相关的体验时，必须先确认时钟真实推进。
本仓库的做法是在页面里挂一个持续的 rAF 动画迫使浏览器保持合成。
